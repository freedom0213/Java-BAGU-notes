# 一、Spring（45 题）

#### 1：什么是 IOC 和 DI？Spring 是怎么实现控制反转的？

IOC是一种控制反转思想，指的是将创建对象的主动权由自己更换为IOC容器，在传统java开发中，想创建一个对象，你只能自己new一个对象然后赋值，而使用Spring后创建对象的活就交给了IOC容器；然后DI是IOC的一种实现方案也就是依赖注入，也就是自动的将注册到IOC容器的Bean分配给需要的对象中（什么是Bean，也就是被IOC管理的类的实例）  

#### 2：BeanFactory 和 ApplicationContext 的区别？

两个都是关于Bean的管理的接口，比如对bean的创建 删除 修改 都能用这两个接口，但是两者的Bean创建时间不一样，BeanFactory是懒加载，即使Spring再扫描到明确有@component需要归于Spring管理的，依然是先不创建而是等到真的用的时候再创建，而ApplicationContext是在扫描到需要spring管理的类直接创建Bean到IOC容器中。  

#### 3：Spring Bean 的完整生命周期是怎样的？

spring启动之后，会扫描加上哪些需要被Spring管理的类，然后找到后会先得到Bean的定义，意思是我现在要创建一个Bean对象，于是Spring通过构造方法创建Bean实例，然后就会依赖注入，注入到需要对象中比如 @autowired private UserMapper usermapper；就会自动注入 usermapper；然后经过一系列初始化步骤，最后Bean创建完成然后使用，当Spring关闭的时候，IOC容器会自动把Bean都销毁  

#### 4：Spring Bean 有哪些作用域？单例 Bean 是线程安全的吗？

作用域就是指IOC容器中可以存在几个同类型的Bean，一般有两种：允许单例和允许多例，单例就是只能存在一个同类型Bean，多例就是每次new对象的时候都会创建一个Bean到IOC容器中。  

#### 5：构造器注入、Setter 注入、字段注入的区别？为什么推荐构造器注入？

构造器：public UserMapper （OrderMapper orderMapper）  
Setter注入：public UserMapper set（OrderMapper orderMapper）{this.orderMapper = orderMapper}  
字段注入：@autowired private UserMapper userMapper；  
这三者都是依赖注入实现方式，同时都能加@autowired  
为什么推荐构造器注入？因为构造器注入使得每一个对象的创建都一定包含它所需要的对象，这样就避免了A对象创建了但是B缺了。  

#### 6：@Autowired 和 @Resource 的区别？

当存在IOC容器有多个同类型Bean时候，这两者才有区别  
@Autowired根据对象类型去IOC中找Bean，当存在多个同类型时候往往需要伴随使用@Qualifier  
@Resource根据对象名称找Bean。  

#### 7：@Qualifier 和 @Primary 的区别？多个同类型 Bean 时如何注入？

@Qualifier一般伴随@autowired使用，@Qualifier(userMapper1) 表示我要找的是UserMapper类型的叫userMapper1实例对象的，通常放在需要依赖注入的地方  
@Primary 表示默认，通常加在创建对象的上面，表示这个对象被创建到IOC容器中，以后这个Bean就是默认值。  

#### 8：@Component、@Service、@Repository、@Controller 的区别？

@Service、@Repository、@Controller都属于@Component，只不过@Service只是表示代表这个Bean是业务模块，@Repository代表持久层模块，@Controller代表请求层模块，只不过现在并不用@Repository而是用@mapper  ,@Controller 用@restController，@Controller其实还有其它作用，也就是注册到IOC后表明是请求层模块，之后的SpringMVC会自动找请求曾模块的Bean。  
为什么？因为传统@Repository在接收到DAO对象（专门处理数据访问层对象 比如UserMapper）后调用方法还得自己写类，而@mapper直接表明在调用mapper接口方法的时候帮我注册一个代理对象然后帮我代理执行，就不需要再自己创建一个class。  
而原始@Controller不能对返回值进行加工，而@RestController=@Controller+@responseBody  

#### 9：@Bean 和 @Component 的区别？分别在什么场景使用？

@Bean表示该方法返回值交给Spring管理，@component表明该类交给Spring管理，通常 @Component 写在自己写的类想要交给Spring管理，而@bean写在一些第三方类或工具 想归于Spring管理  
为什么第三方类不能用@component？因为你要想写@component必须加在类上面，这直接修改了类的具体代码，而源码是不可以更改的。

#### 11：Spring 三级缓存分别存什么？如何解决循环依赖？

一级：Bean本体  
二级：bean半成品  
三级：bean半成品的工具；一般循环依赖可以直接利用二级缓存解决，但如果出现循环依赖+AOP，那么为了避免A依赖B，B最终获取A的代理对象，A使用的是A的本体，这样对象不一致情况使用3级缓存。  

#### 12：为什么构造器注入的循环依赖无法解决？@Lazy 为什么能解决？

因为构造器注入比如Public  A(B b);这表明构造器注入A的时候是明确A必须有B才能创建，如果B也是这样就会陷入循环，即使是三级缓存也没用；此时在参数B b加上@Lazy就能解决，同样是构造器注入，但不同的时候在需要B的时候先不是创建B的对象而是给B一个代理对象，有B了然后A正常创建，创建后如果真实情况中真正需要B的时候，这时候Spring真正创建B；  

#### 13：Spring AOP 的实现原理？JDK 动态代理和 CGLIB 的区别及选择时机？

SpringAop底层是通过动态代理实现的，也就是当一个类被Spring注册为一个Bean的时候，当需要该Bean对象执行方法等等行为时候，通常不直接使用该Bean对象，而是动态地创建该Bean对象地代理对象，在使用代理对象执行操作时候，会先对方法进行AOP拦截器拦截执行切面编程，比如日志，事务，鉴权等等在执行目标操作；而JDK 动态代理和 CGLIB 都是动态代理地方式，不同的是JDK动态代理基于接口创建代理对象，比如Public Interfence UserService 然后这是一个接口，对象实例就不是IMPL而是代理对象，CGLIB基于创建目标类的子类作为代理对象，但被Final修饰地类或者方法不能通过该方法被处理，现代Spring默认使用CGLIB。  

#### 14：Spring AOP 有哪些通知类型？为什么 Around 最强大？

Before After AfterReturning AfterThrowing Around，因为Around可能在目标方法执行前后都能执行逻辑，控制能力很强，并且还能获取目标方法地各种参数和返回值  

#### 15：AOP 在哪些情况下会失效（同类内部调用、private 方法、final 类等）？

SpringAop是基于代理对象实现的，所以如果绕过代理对象用其它对象执行目标方法，那么AOP就会失效，所以就有几种情况：同步内部类（this.xxx()），private，final，还有自己new的对象，也就是没有被Spring管理地对象。

#### 17：@Transactional 的实现原理？它是怎么生效的？

之前在学习AOP的时候，AOP原理就是创建目标对象地代理对象，然后让代理对象在目标方法执行过程中多出来几步任务，所以事务@Transactional其实也是AOP地一种，所以@Transactional加在类或者方法上表示目标类的事务代理对象，然后如果执行方法，那么会经过事务拦截器，拦截器会通过事务管理器开启事务然后执行目标方法，方法正常执行，事务提交，否则回滚；  

#### 18：@Transactional 失效的场景有哪些？（请尽可能完整列举）

同一个类中的内部方法调用；private方法(动态代理底层是构建目标类子类继承方法，private,final方法不支持继承重写)，没有被spring管理。

#### 20：Spring 事务的隔离级别有哪些？和数据库隔离级别的对应关系？

#### 22：Spring MVC 一次请求的完整处理流程（DispatcherServlet 到响应返回）？

SpringMVC是一个架构，MVC是一种思想：把接收请求调用业务C，处理数据M，展示页面V给分隔开  
SpringMVC流程：先是前端发送一个请求：Get /user/1001，然后会到达Spring的内置服务器Tomcat，Tomcat负责调用servlet，DispatcherServlet就是一个servlet，然后TomCat会把请求转发给SpringMVC总入口：DispatcherServlet，然后DispatcherServlet会找到对应的Controller，这时候就会根据SpringMVC相关注解 比如@requestMapper("/user") 映射，总入口会把请求扔向有这个注解的Controller类，然后再根据@GetMapping("/{id}") 最后锁定目标方法，最后调用业务返回json结果利用http响应返回。  
Tomcat：监听端口 解析请求 调用servlet  

#### 23：@Controller 和 @RestController 的区别？

@Controller 和 @RestController 都能将类注册为Bean，然后分块都是关于接受请求返回数据的，不过最不同的是@RestController=@Controller+@responseBody   @RestController能将返回值封装为一个json对象，这个json对象会包装在Http响应的Body里面；而@Controller返回的是“user”，那么Sprinmvc就会找对应页面：templates/user.html  

#### 24：@RequestParam、@PathVariable、@RequestBody、@ModelAttribute 的区别与适用场景？

这四个注解都是SpringMVC注解，用于将http请求中的数据转化为java参数  
@RequestParam：Get /user?id=1001  表示路径上的参数  
@PathVariable：Get/user/1001	表示路径上的变量  
@RequestBody：Post /user   {json}   表示请求传给一个json数据需要转化为java对象  
@ModelAttribute：暂不常见 不考虑  
通常@RequestParam、@PathVariable会搞混：@RequestParam常用来进行筛选查询 查询列表而@PathVariable表示具体查询目标id的详细数据 查询详情  

#### 25：Filter、Interceptor、AOP 的区别？执行顺序是怎样的？

首先Filter、Interceptor、AOP都有拦截功能，但是三者的拦截时机不同，按顺序的拦截顺序是：Filter->Interceptor->AOP  
Filter是Http，会将传来的http请求拦截然后鉴权查看请求header是否含有token  
Interceptor拦截是SpringMVC层，一般作用是在调用Controller层时候判断是否有权限  
AOP：拦截一般是业务层 比如开启事务 统一拦截  

#### 26：全局异常处理怎么做？@ControllerAdvice + @ExceptionHandler 的原理？

全局异常处理确实也是一个拦截功能，但全局异常处理既不属于Filter，也不属于Interceptor，而是属于Spring MVC 的异常解析机制，发生在Controller方法执行过程中出现的异常处理  
为什么需要全局异常处理？比如Controller层调用业务方法，但是业务方法可能会抛出来异常，Controller会得到异常但是没有异常处理，就不知道该怎么办，然后异常也暴漏出来，所以希望会有全局异常处理器，对全局的异常进行处理。  
通常@ControllerAdvice + @ExceptionHandler会一块使用，@ControllerAdvice意思是给全局所有Controller的Bean提供解决异常的能力，比如普通Controller：@requestController public class UserController{}，然后调用业务方法抛出异常没法处理，这时候创建一个全局异常处理器

#### 27：Spring Boot 自动配置的原理（从 @SpringBootApplication 到 AutoConfiguration.imports）？
