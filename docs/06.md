### （一）索引

#### 1：MySQL 的整体架构分层是怎样的（连接器、查询缓存、分析器、优化器、执行器、存储引擎）？

在回答MqSQL的整体架构分层之前，我们要知道Mysql是一个关系型数据库，什么是关系型数据库呢？意思就是数据以二维表结构存在+表之间通过字段建立关系：比如一个User表和一个Order表，那么Order表就可以通过Userid让两个表建立关系。  
Mysql整体架构：连接器、查询缓存、分析器、优化器、执行器、存储引擎  
首先java代码想使用Mysql必须要与Mysql建立网络连接（连接器），之后客户端传来sql语句，mysql会先判断是否存在相同sql结果的缓存（查询缓存：之后新版本 Mysql抛弃了查询缓存功能，原因是mysql更新太频繁了），之后如果没有缓存，就需要将sql语句拆解分析，判断sql语句是否正确（分析器），之后通过优化器决定SQL怎么执行，之后执行器开始真正执行SQL，调用存储引擎InnoDB获取数据。  

#### 2：InnoDB 和 MyISAM 的区别？为什么默认选 InnoDB？

其实就是因为在现在的网络环境下，往往需要高并发情况下的安全性和高效性，在这种场景下InnoDB明显要比MyISAM好的，本质是因为InnoDB存储引擎具有事务功能+行锁（解决高并发问题），而MyISAM没有事务功能，虽然也能加锁但是表锁，也就是一个请求进行修改数据的时候是对整个表进行加锁，其它请求若也想修改同一个锁只能阻塞等待，而InnoDB是行锁，也就是只对表的哪一行数据加锁。  

#### 3：B+ 树的结构是怎样的？为什么 InnoDB 用 B+ 树而不用 B 树、红黑树或 Hash？

首先我们要知道普通二叉树就是一个根两个子节点，一左一右，为了区分大小便于查询，有了二叉搜索树 规定了左子树<根<右子树的规则，查询时候只要根据这个规则就能快速查询，但是如果根设计的不合理就会出现所有节点都在右子树，最坏情况下查询还是O(n)，所以需要红黑树：红黑树是一种自平衡二叉搜索树，确实避免了这样的情况，但是对于数据库来说，数据是几万的，如果还是走二叉风格，树的高度会堆得很高很高，所以这时候有了B树：B树是什么？B树是一个节点可以存多个数据的树结构  
[30 50 70]  

/    |    |    \  
10    40   60    90  
每一个非叶子节点都可以类似于数组那样，放多个数据，这样有效的降低树的高度  
B+树是对B树的一种优化：非叶子节点：只存索引，叶子节点：存真正数据  
如何使用呢？：这其实就分为普通索引和主键索引，当用户需要根据name字段查数据，首先会查询普通name的B+树，从而找到name对应的主键，然后根据主键索引B+树，找到所需要的数据，注意：正常情况下 mysql会自动生成主键索引，而其它普通索引需要自己创建维护。  
为什么存储引擎InnoDB不使用B树呢？因为：因为B树每一个节点都会存数据原因，当表结构很复杂时候，导致一个数据就很大，那么这个树存储大小就很大，导致存的节点个数就会有限制  
为什么不使用hash？因为当sql语句根据age>10来查询，但是经过hash计算 这个10就会变成其它的数。  

#### 4：聚簇索引和二级索引的区别？什么是回表？

首先我们要知道什么是聚簇索引和二级索引：  
聚簇索引指的是索引和数据绑在一起，意思是可以根据索引直接找到数据，在B+树里面指的是主键索引，而二级索引或者就是普通索引，就是现根据二级索引找到主键，然后根据聚簇索引找到数据这种方式  
为什么二级索引也不保存完整数据？因为如果保存完整数据就会造成数据重复，改动数据的时候还需要同步。  
什么是回表：当查询name where age=10，这时候会查询二级索引age树 查询到主键，但是我们要的是name值，这时候就会回到聚簇索引找到完整数据找到name值，这个过程就是回表过程。  

#### 5：什么是覆盖索引？如何利用它优化查询？

覆盖索引就是利用二级索引直接找到数据不回表情况，说白了就是查询二级索引已有的数据，这样就不需要回表了，这样的过程就是覆盖索引。  

#### 6：什么是最左前缀原则？联合索引应该怎么设计（列顺序怎么定）？

最左前缀原则专门用来处理联合索引的，什么是联合索引，就是一个B+树，但是筛选条件有多个，这样的索引或者B+树就是联合索引，所以为了解决多个条件如何查询设计了最左前缀原则，也就是当声明索引的时候  
CREATE Index index_user_status  
ON orders(user_id,status)，在设计索引的时候把user_id放在前面就是指先筛选user_id，在筛选status，不能先筛选status。  
怎么设计？将做经常做查询条件字段放前面，将有辨识度的条件放前面  

#### 7：索引在哪些情况下会失效？（请尽量完整列举）

1：将索引函数化：  
CREATE INDEX idx_time  
ON user(create_time);    索引是create_time，但是在查询的时候写成：  
SELECT *  FROM user   WHERE   YEAR(create_time)=2026;你以为能够将索引经过函数YEAR计算直接利用年份比较，实际上create_time索引记录的都是2025-01-05；这样的数据  
2：Like前面加%：正常：Where name Like "张%"，  
错误写法：Where name Like  "%三"；因为mysql引擎不知道如何找到以“三”为结尾的，只知道会找到以“张”为开头的。  
3：违反最左前缀原则：  
CREATE Index index_user_status  
ON orders(user_id,status)  
不能先根据status找，这样索引就失效了。  
4：隐式类型转换：  
CREATE INDEX idx_phone  
ON user(phone);  phone字段是一个varchar(11)字符串，但是用来Where phone = 1001。这样就是错的。

### （二）事务与锁

#### 11：事务的 ACID 分别是怎么实现的？（undo log、redo log、锁 + MVCC）

ACID：分别指的是：原子性，一致性，隔离性，持久性  
原子性就是指：操作要么同时成功要么同时失败，利用undo log。在修改数据之前会在undo log文件中记录修改之前的数据，这样事务回滚就能恢复成正确数据  
持久性：例如当对数据做出修改，并且已经提交，但是提交后mysql崩了，数据可能并没有持久化到硬盘中，这时候就需要redo log，首先mysql虽然是一个硬盘数据库，但并不是commit后就存到硬盘了，那样的话修改一次就动一次磁盘压力会相当大，其实因为mysql是有内存的，它commit的时候会先存到内存中，然后记录redo log，记录写操作，然后内存提交到硬盘，所以当mysql崩溃可以读取redo log文件，快速恢复修改磁盘  
隔离性：（隔离就是指如何在并发安全情况下保证数据得正确性安全性。）锁+MVCC：锁是一定要要有的->谁给的？InnoDB存储引擎改的，如果并发修改同一行数据会对一个线程加行锁保证并发写问题，并发读写呢？比如一个线程写，一个线程读，但如果写没有写完，那么读到底那个数据呢？？这个是时候使用：MVCC，记录历史数据然后让读操作读到自己能够读到的数据  
一致性：一致性是基于原子性，隔离性，持久性最终完成得最终一致性。  

#### 12：四大隔离级别分别解决什么问题？MySQL 的默认级别是什么？为什么？

四大隔离级别：读未提交，读已提交，可重复读，串行化  
读未提交（READ UNCOMMITTED）：最低的隔离级别，当并发时A线程修改数据还没有提交的时候B线程就能读取未提交数据，如果A线程最后提交失败回滚，那么B线程读取的就是脏读数据。  
读已提交（READ COMMITTED）：所以为了解决脏读问题，就有了读已提交级别，规定线程只能读取已提交得数据，但是如果一个线程B开启事务读取数据，第一次读取1000，第二次读取前A修改了数据1000->800，那么线程B在同一个事务中又读取了800了数据，前后不一致造成不可重复读问题  
可重复读（REPEATABLE READ）：为了解决不可重复读问题，即同一个事务中，多次读取同一数据，应该保持一致，这个隔离级别主要依赖MVCC，即同一个事务会读取同一个MVCC快照，保证同一个事物数据得一致性，可重复读隔离级别可以一定得环节幻读问题：对于普通select（普通读就是快照读），使用MVCC得undo log得快照即可，对于当前读（就是读最新数据）：  
SELECT * FROM user WHERE age > 18  FOR UPDATE;需要加锁防止在读的时候有其它出局插入进入，这种加锁通常是InnoDB的行锁，对这一行数据进行加锁。  
串行化：最高隔离级别：事务A->执行->完成->事务B->执行->完成。  

#### 13：脏读、不可重复读、幻读的区别与示例？

脏读就是读取到其它线程未提交数据，然后这个数据还没有成功提交，那么读取读取到的这个数据就是脏数据  
不可重复读：在一个事务中读取同一个对象却又两个不一样结果  
幻读：在一个事务中，两次读取不仅是结果不一样，而且一个读取AB，一个读取ABC（原因：在第一次读取完后，其它线程有增添了数据）

#### 15：快照读和当前读的区别？RR 级别下能完全解决幻读吗？

在一个事务中快照读也就是普通读，select * from user where age=10；而当前读就是指读取最新的数据，也就是当一个线程写操作到达commit地步，当前读也能把这个最新数据读取出来  
RR（可重复读）可以利用MVCC（不看到新数据）解决普通快照读的幻读问题，而对于当前读 for update 使用记录锁 + 间隙锁锁住符合条件的记录以及相关范围，此时其它线程插入数据的时候如果插入符合范围的数据会因为收到间隙锁范围限制就会拒绝插入新数据。  

#### 16：InnoDB 有哪些锁（行锁、间隙锁、临键锁、意向锁、插入意向锁）？各自的作用？

行锁：对数据库的一行数据写的时候进行加锁，排他锁  
间隙锁：对数据库的数据范围比如10-20进行加锁 也就是范围锁，其他数据不能插入到这个范围进去（但是通常间隙锁只对范围加锁，对左右10 20节点不加锁，所以此时也需要行锁对左右端点加锁）。  
临建锁：行锁+间隙  
插入意向锁：表示声明我要在10-20这个范围内插入数据了，其它人不要影响我，如果这时候出现间隙锁，将10-20范围加锁，那么就差插入失败进行重试等待。  
意向锁：意向锁其实是一个表级锁，告诉系统“表里某些行有行锁”，方便如果想加表锁，可以通过意向锁快速得知 表中已经存在行锁。
